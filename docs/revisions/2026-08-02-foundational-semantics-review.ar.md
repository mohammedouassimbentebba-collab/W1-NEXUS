# مذكرة مراجعة الدلالات التأسيسية — 2 أغسطس 2026

## سبب المراجعة

بعد تثبيت الحوكمة ظهرت مسائل مشتركة ستؤثر في جميع المخططات: الفرق بين الفاعل والمسجل وصاحب الصلاحية، وترتيب الأحداث عند اختلاف الساعات، وثبات مراجع الكيانات، ومنع الكتابة على إصدار قديم، وحدود الثقة غير المعايرة.

عولجت هذه المسائل قبل تصميم `ProtocolEnvelope` و`EntityRef` و`VersionedEntity` حتى لا تتكرر دلالات مختلفة في الكيانات اللاحقة.

## القرارات المعتمدة

| المجال | القرار في v0.1 |
|---|---|
| المساءلة | فصل `actor` و`on_behalf_of` و`authorized_by` و`recorded_by` |
| الدور | إسناد جلسي مستقل عبر `role_assignment_id` ونطاق صلاحية |
| ترتيب الأحداث | `session_id + sequence` هو المرجع الرسمي |
| الأزمنة | فصل وقت الوقوع المدعى عن الاستلام والتسجيل |
| مراجع الكيانات | النوع والمعرف والإصدار مطلوبة في السجلات المعيارية |
| ثبات الكيانات | كل تعديل دلالي ينشئ إصدارًا جديدًا غير قابل للاستبدال |
| التزامن | رفض التعديل إذا خالف `expected_entity_version` الإصدار الحالي |
| الادعاءات | تصنيف قابلية التحقق إلى حتمي وتجريبي ومصدري وحكم بشري وغير متاح حاليًا |
| طرق التحقق | تسجيل الإصدار والمصدر والافتراضات وحالة الصلاحية |
| الاعتراض | هدف موحد مثبت بالإصدار، مع إعادة فتح مضبوطة |
| القرارات | اعتماديات صريحة وحالة `reassessment_required` |
| الثقة | مستوى وصفي افتراضي؛ الأرقام المحلية غير قابلة للمقارنة دون معايرة مشتركة |

## حدود التعديل

لم تنشأ مخططات JSON أو تطبيقات تنفيذية في هذه المراجعة. كما لم يثبت الشكل النهائي للكيانات التأسيسية الثلاثة؛ حددت متطلبات قبولها الدلالية فقط.

بقي التوقيع والتجزئة التشفيرية والمعايرة الموحدة للثقة خارج نطاق `v0.1`.

## بوابة المرحلة التالية

لا يبدأ تصميم بقية الكيانات قبل:

1. مراجعة اتساق الدلالات التأسيسية مع نموذج الحوكمة ونطاق الإصدار.
2. اعتماد تصميم `ProtocolEnvelope`.
3. اعتماد تصميم `EntityRef`.
4. اعتماد تصميم `VersionedEntity`.

أي تعديل لاحق في دلالات هذه العقود يجب أن يراجع أثره في جميع المخططات التابعة.
