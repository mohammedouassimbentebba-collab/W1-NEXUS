# مذكرة إغلاق الدلالات التأسيسية — 2 أغسطس 2026

## الغرض

تسجل هذه المذكرة الدفعة الأخيرة التي سبقت تصميم `ProtocolEnvelope` و`EntityRef` و`VersionedEntity`. أغلقت الدفعة قواعد مساحة الهوية، وعدم قابلية تعديل الإصدارات، والتزامن التفاؤلي، وتصنيف التغييرات، وسند الصلاحية، وفئات الأحداث، واعتماديات القرار.

## القرارات النهائية

| المجال | القرار |
|---|---|
| مساحة الهوية | `session_id + entity_type + entity_id`، مع lowercase ومنع إعادة الاستخدام |
| إنشاء الكيان | يتطلب `expected_absent: true` ويرفض التعارض بـ`entity_already_exists` |
| ثبات الإصدار | أي تغيير في الحمولة القانونية ينشئ إصدارًا جديدًا كاملًا |
| التعديل المباشر | يرفض دائمًا بـ`immutable_version` |
| التزامن | `expected_entity_version` شرط لإنشاء الإصدار التالي، والتعارض `version_conflict` |
| سبب التغيير | `semantic` أو `editorial_correction` |
| أثر التغيير | الافتراضي `may_affect_dependents` |
| التصحيح غير المؤثر | يحتاج `classify_editorial_correction` وفحصًا مسجلًا |
| الـDiff | أثر مشتق؛ الحمولة الكاملة لكل إصدار هي المصدر القانوني |
| سند الصلاحية | `EntityRef` مثبت لإصدار صالح عند `recorded_at` |
| فئات الأحداث | بروتوكولية وتشغيلية وأمنية؛ البروتوكولية وحدها تغير الحالة |
| السببية | سبب مباشر واحد؛ `related_events` للسياق فقط |
| البيانات الحساسة | لا تنسخ إلى سجل التدقيق، مع إبقاء بيانات حجب مجردة |
| اعتماديات القرار | رسم لا دوري وسياسات `notify/reassess/invalidate/block` |
| الاعتراض الحرج | ينشر إعادة التقييم عبر الاعتماديات الفعلية المسجلة فقط |
| الثقة | لا تمنح سلطة ولا تعوض الدليل أو التحقق |

## فصل قاعدتي الإصدار

لا تعني صحة `expected_entity_version` جواز تعديل الإصدار السابق. القاعدتان مستقلتان:

```text
Immutability:
accepted version payload mutation → immutable_version

Optimistic concurrency:
stale base for next version → version_conflict
```

المسار المقبول هو إنشاء إصدار تالٍ يتضمن مرجع الإصدار السابق وحمولة قانونية كاملة وسبب التغيير وأثره، مع إبقاء الإصدار القديم دون تعديل.

## إبطال تصنيف التغيير

إذا ظهر أن تصحيحًا تحريريًا أخفى أثرًا دلاليًا، لا تعدل بيانات الإصدار التاريخية. ينشأ حدث `entity.change_classification_invalidated`، وتنتشر إعادة التقييم عبر الاعتماديات المسجلة.

لا يعد حجم الفرق النصي أو عدد الأحرف دليلًا على عدم وجود أثر دلالي.

الخطوة التالية، بعد مراجعة الملفات، هي تصميم:

```text
ProtocolEnvelope
→ EntityRef

```
