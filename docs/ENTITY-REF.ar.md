# EntityRef — W1-CIP v0.1

## 1. الغرض

يعرّف `EntityRef` مرجعًا مثبتًا إلى **إصدار واحد غير قابل للتبديل** من كيان داخل جلسة `W1-CIP`. يجيب المرجع عن السؤال: أي كيان، وأي إصدار منه، استُعمل في القرار أو الاعتراض أو التحقق أو الحدث؟

لا يثبت المرجع وجود الكيان فعليًا، ولا صلاحية استعماله، ولا سلامة محتواه. تتحقق هذه الأمور في مخزن الجلسة وقواعد الحوكمة.

## 2. البنية

```yaml
entity_type: contribution
entity_id: claim-21
entity_version: 2
```

الحقول الثلاثة إلزامية، ولا يسمح بخصائص إضافية.

- `entity_type`: نوع الكيان بصيغة lowercase.
- `entity_id`: معرف الكيان بصيغة lowercase.
- `entity_version`: عدد صحيح موجب يبدأ من `1`.

معرّف المخطط:

```text
urn:w1-cip:schema:0.1:entity-ref
```

## 3. نطاق الجلسة

مساحة الهوية القانونية للكيان هي:

```text
session_id + entity_type + entity_id
```

لا يحمل `EntityRef` حقل `session_id` لأن المرجع في `v0.1` لا يعبر حدود الجلسة؛ تأتي الجلسة من `ProtocolEnvelope` أو من الكيان الحاوي. لذلك لا يجوز نقل المرجع وحده خارج سياقه واعتباره مرجعًا عالميًا. المراجع بين الجلسات خارج نطاق `v0.1`.

## 4. التثبيت بالإصدار

لا يسمح بمرجع متحرك مثل:

```yaml
entity_version: latest
```

كل سجل معياري محفوظ يجب أن يثبت رقم الإصدار الذي استعمله. وإذا ظهر إصدار أحدث يبقى القرار أو الاعتراض القديم مرتبطًا بالإصدار السابق حتى تنشأ إعادة تقييم مسجلة.

## 5. EntityIdentity

يتضمن المخطط تعريفًا مساعدًا غير مصدّر باسم `entity-identity`:

```yaml
entity_type: contribution
entity_id: claim-21
```

يستخدم فقط عندما يطلب أمر `create` إنشاء هوية متوقع غيابها مع `expected_absent: true`. لا يجوز استعماله بدل `EntityRef` داخل قرار أو اعتراض أو تحقق محفوظ لأنه لا يثبت إصدارًا.

مرجع التعريف المساعد:

```text
urn:w1-cip:schema:0.1:entity-ref#entity-identity
```

## 6. الاستعمال داخل ProtocolEnvelope

يستخدم `EntityRef` في:

- `entity`: الإصدار الناتج أو موضوع الحدث.
- `precondition.target`: الإصدار السابق عند إنشاء إصدار تالٍ.
- `authorized_by`: إصدار `role_assignment` أو `approval` الذي منح السلطة.

أما `precondition.target_identity` فيستعمل `EntityIdentity` لأن الكيان لم يوجد بعد.

يقيد `ProtocolEnvelope` نوع `authorized_by.entity_type` إلى `role_assignment` أو `approval`، لكن `EntityRef` نفسه يبقى عامًا لجميع أنواع الكيانات.

## 7. ما يفرضه المخطط

يفرض JSON Schema:

- الحقول الثلاثة المطلوبة.
- lowercase ونمط المعرفات.
- رقم إصدار صحيح موجب.
- منع الخصائص الإضافية.
- منع القيمة النصية `latest` أو أي مرجع غير مثبت.

وتبقى لقواعد الجلسة:

- وجود الإصدار المشار إليه داخل الجلسة نفسها.
- عدم إعادة استعمال الهوية.
- صلاحية المرجع بالنسبة إلى العملية.
- منع الإشارة إلى إصدار مستقبلي أو محذوف منطقيًا إذا منعت السياسة ذلك.

## 8. أمثلة الاختبار

توجد أمثلة مستقلة لـ`EntityRef` و`EntityIdentity`، تشمل مراجع صحيحة ورفض الإصدار المفقود أو الصفري أو المتحرك، والأحرف الكبيرة، والخصائص الزائدة.
