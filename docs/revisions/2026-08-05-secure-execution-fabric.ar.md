# مذكرة اعتماد W1 Secure Execution Fabric

**التاريخ:** 2026-08-05  
**الحالة:** معتمد للتنفيذ المرجعي `dev28`

## القرار

اعتماد طبقة تنفيذ ثنائية المسار:

1. OCI عبر Docker أو Podman للعزل الصلب.
2. Local بحدود POSIX للأعمال الموثوقة فقط.

يمنع النظام الهبوط الصامت من Profile تتطلب عزلًا صلبًا إلى Local.

## الضوابط المعتمدة

- SandboxProfile مصدرة ومسجلة ببصمة.
- أوامر `argv` دون Shell.
- حدود للوقت والذاكرة وCPU والعمليات والملفات والخرج.
- شبكة مغلقة افتراضيًا في OCI.
- Root filesystem للقراءة فقط.
- إسقاط capabilities و`no-new-privileges`.
- Mount roots محددة في Profile.
- أسرار مؤقتة لا تدخل السجل، مع تنقيح القيم المعروفة من stdout وstderr.
- استخراج Artifacts دون symlinks وبحد حجم.
- HMAC Attestation محلية.
- Idempotency حسب `execution_id` وبصمة الطلب.
- قتل مجموعة العملية أو الحاوية عند المهلة والإلغاء.
- تكامل اختياري لكل AgentJob في Parallel Runtime.

## تصحيحات ظهرت أثناء التنفيذ

- استبدال `preexec_fn` بمشغل فرعي يطبق `setrlimit` ثم `exec`، لأن التشغيل المتوازي متعدد الخيوط لا يناسب `preexec_fn`.
- استبدال تجميع الخرج بعد النهاية بقارئات مستمرة محدودة الذاكرة.
- إضافة قتل صريح للحاوية عند قتل عميل Docker أو Podman.
- منع Mounts خارج الجذور المعلنة.
- جعل التنفيذ المكرر بالطلب نفسه idempotent.
- الفصل الصريح بين حدود OCI الصلبة وحدود Local غير الكاملة.

## قرار المخاطر

Attestation الحالية محلية وليست ضمانًا ضد مهاجم يسيطر على المضيف أو مفتاح W1 المحلي. كما أن Local ليس عزلًا مناسبًا للكود العدائي. يجب استخدام OCI أو VM عند تشغيل كود غير موثوق.

## المرحلة التالية

تنتقل W1 Nexus بعد هذه الخطوة إلى طبقة **Long-Term Memory + Knowledge Fabric** مع الحفاظ على Secure Execution Fabric كأساس لكل Agent Runtime وComputer Use لاحقًا.
